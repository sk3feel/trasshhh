# Большой A100-эксперимент: самостоятельные notebooks

Основной код нового обучения — **только** [Colab_train_A100.ipynb](notebooks/Colab_train_A100.ipynb). Отдельный [Colab_inference_T4.ipynb](notebooks/Colab_inference_T4.ipynb) содержит весь код инференса. Оба работают через Run all в чистой сессии после выбора GPU и подтверждения Drive. Git clone, импорты `src`, HF/Comet/API keys и загрузка наших скриптов не нужны. Веса создаются случайно; `from_pretrained` используется только для загрузки собственных сохранённых экспортов.

## Запуск за 8 шагов

1. Загрузите локальный `deliverables/colab_training_data.zip` **одним ZIP без распаковки** в `My Drive/nlp_hw2/colab_training_data.zip`. Подкаталог `nlp_hw2` создайте на Drive заранее. Архив: **860 992 113 байт**; распаковка: **1 695 635 353 байт**. Рекомендуется дополнительно свободных **10 GiB на Drive**, **20 GiB на локальном диске runtime**. Данные/веса не хранятся в GitHub.
2. Откройте [training notebook в GitHub](https://github.com/sk3feel/trasshhh/blob/colab-large-experiment/notebooks/Colab_train_A100.ipynb) через Colab и выберите A100. Для неизменной версии используйте permalink конкретного commit вместо имени ветки. Первая ячейка уже настроена на указанный Drive: `DRIVE_ROOT`, `DATA_ARCHIVE`, новый `RUN_NAME`, `RESUME_FROM=None`, бюджет 6 часов. При стандартном пути менять ничего не надо.
3. Сразу нажмите **Runtime → Run all**, подтвердите Drive. Подготовка вместе с benchmark ≤20 минут; benchmark ≤10 минут; две LR-пробы вместе ≤40 минут; основное обучение ≤4 ч 30 мин. Общий предел A100 **6 часов**, последние **30 минут без updates** для сохранения/оценки/экспорта. Медленная подготовка сокращает обучение. Время от подключения GPU до первой ячейки код не измеряет — подключайтесь непосредственно перед запуском.
4. Дождитесь `completion.json` и сообщения **DRIVE EXPORTS VERIFIED AND LOADABLE**. Результаты — `My Drive/nlp_hw2/runs/<RUN_NAME>/`: `configs/`, `logs/`, `checkpoints/`, `validation_predictions/`, `exports/`, `review_bundle.zip`. После этого **Runtime → Disconnect and delete runtime**: завершение Python само не отключает платный runtime. При ошибке Drive не считайте сохранение завершённым: сначала скачайте локальные файлы `/content/nlp_hw2/runs/<RUN_NAME>/`.
5. Скачайте `review_bundle.zip` на этот компьютер и выполните `python3 scripts/evaluate_colab_review.py --review /путь/review_bundle.zip --output deliverables/colab_numeric_review`. Нужны работающий Docker и уже существующий pinned Python image из `src/sandbox.py`; generated-код исполняется только там. Команда проверяет порядок 512 вопросов, frozen references и оценивает все доступные проверенные экспорты по прежним **493** числовым references; `rtol=atol=1e-6`. Передайте обратно ZIP и `summary.json`. Кандидаты без полной генерации явно пропускаются.
6. Откройте [T4 notebook](https://github.com/sk3feel/trasshhh/blob/colab-large-experiment/notebooks/Colab_inference_T4.ipynb) в **новой чистой T4-сессии**. `EXPORT_PATH=None` выбирает CE-кандидата последнего завершённого запуска. После локальной проверки при необходимости укажите путь к выбранному кандидату: `/content/drive/MyDrive/nlp_hw2/runs/<RUN_NAME>/exports/<candidate_name>`. `INFERENCE_BATCH=64` независим от train batch. Нажмите Run all и подтвердите Drive.
7. Скачайте `t4_results.zip` по ссылке последней ячейки или из папки результатов на Drive. В нём `submission.jsonl`, `timing.json`, `generation_parameters.json`, `predictions.json`, `submission_validation.json`, `inference.log`. Боту предназначен **только submission.jsonl**: ровно 1919 строк в исходном порядке, каждая `{"code":"..."}`. Notebook сам боту ничего не отправляет. Greedy/max256 — явно согласованная настройка этого эксперимента; рекомендация бота «64 токена» не является принудительным обрезанием программы.
8. Отключите T4 вручную через **Disconnect and delete runtime**. Отведите ей максимум **30 минут**, включая setup/copy/генерацию/сохранение; общий облачный предел A100+T4 — **6,5 часа**. Передайте обратно `t4_results.zip` для анализа фактических generation/pipeline timings.

## Что именно исполняется

Ячейки обучения идут последовательно: настройки/таймер → Drive/проверенные записи → зависимости/A100/BF16 → mmap-данные/split → модель/update/resume → benchmark → две LR-пробы → основное обучение → финальное сохранение → переносимые экспорты. Функции находятся прямо в ячейках; локальные тесты извлекают определения из notebook, собственной реализации training loop в тестах нет.

Модель: random BART encoder6/decoder6, d768, heads12, FFN3072, vocab8192, **106 321 920 параметров**, tied embeddings/LM head, dropout0.1, positions512. Frozen train-only BPE и исходные специальные токены; source≤192/target≤384. Расширенный train **5 820 047 пар**, teacher-forcing validation1500, generation512. Все группы SHA256 нормализованного вопроса `%200==0` исключены из train целиком. Упаковщик повторно вычислил hash каждого train-вопроса из provenance; notebook проверяет frozen hashes, manifests, длины и исключение групп. Никаких новых targets или execution-фильтра.

Данные читаются через NumPy mmap; порядок эпохи — массив индексов NumPy, не список миллионов Python-объектов. Benchmark измеряет реальные разные длины и стресс-блок длинных примеров, warmup отдельно, полезные target tokens/s, examples/s, update seconds, allocated/reserved VRAM; выбирает быстрый вариант с ≥20% запасом. Physical32/64/128/256, effective256; градиент нормируется на число непустых target-токенов всего update, включая неполный последний блок. A100: BF16, SDPA, AdamW, clipping, без compile; CUDA PyTorch из Colab не заменяется. Прогноз эпохи/числа предъявлений рассчитывается после реального benchmark, а не обещается заранее.

LR2e-4/5e-4: одинаковые исходные веса, RNG, порядок и число updates; короткий warmup, затем постоянный peak. Среди полностью завершённых стабильных проб выбирается меньший token-weighted CE. Оба нестабильны/не завершены — диагностика и остановка без поиска новых рецептов. Main заново загружает исходную случайную инициализацию. Planned steps фиксируются один раз с запасом на CE/checkpoints; warmup3%, cosine до0.1peak. CE каждые25 минут, greedy512 примерно раз в час при наличии бюджета. Численная validation и public pass@1 до локальной/официальной оценки неизвестны.

Экспорт каждого кандидата: `model/model.safetensors`, `model/config.json`, tokenizer, generation config, самостоятельный `generate.py`, requirements, manifests и 1919 неизменных вопросов без ответов. До трёх лучших CE-кандидатов плюс final; optimizer/train отсутствуют. T4 notebook содержит тот же inference-код внутри ячейки и не импортирует экспортированный `generate.py`. FP16/SDPA/KV-cache, greedy/max256; load/warmup/generation/full pipeline измеряются отдельно с CUDA synchronization; установка и копирование учитываются отдельно. Число и hashes входов/выходов проверяются. В Colab generated-программы не исполняются.

## Resume и сохранение

В **чистой A100-сессии** укажите прежний `RUN_NAME` и `RESUME_FROM=Path('/content/drive/MyDrive/nlp_hw2/runs/<RUN_NAME>/checkpoints/last.json')`. Остальные настройки оставьте прежними. Benchmark и LR-пробы пропускаются; проверяются implementation/data identity, конфиг и расписание. Восстанавливаются model/optimizer/scheduler/RNG/sampler position/счётчики. BF16 не требует GradScaler. Если указатель повреждён, можно явно выбрать `last.previous.json`.

`budget.json` фиксирует исходный абсолютный deadline. Resume **не выдаёт новые 6 часов**; время между сессиями считается консервативно потраченным, поскольку после внезапного уничтожения VM точный последний GPU-active момент неизвестен. Продолжение возможно только до исходного cutoff. Сохраняйте исходные значения бюджетов. Идентичность кода фиксирует `IMPLEMENTATION_SHA256` (код ячеек без settings) плюс сохранённый конфиг; опубликованный Git commit фиксирует сам notebook. На другом коде resume отвергается.

Полное состояние сначала сохраняется локально, затем под новым именем на Drive; SHA проверяется до смены `last.json`. Предыдущая проверенная копия сохраняется, затем удаляются лишние full states. Кандидаты — только inference-веса. Ошибки Drive видны, локальные артефакты остаются; гарантировать сохранение после внезапной потери VM или зависшего Drive I/O невозможно. Не используем keep-alive/обход лимитов. Эти ограничения согласуются с [Colab FAQ](https://research.google.com/colaboratory/faq.html).

## Проверки, ограничения и остальные файлы

`tests/check_colab_notebooks.py` компилирует все code cells, проверяет embedded config, маски/decoder shift, token-weighted accumulation на разных длинах, неполный блок, optimizer updates, точный CPU-resume с dropout, запрет смены schedule, экспорт/reload и идентичные tiny greedy-ответы, deadline без update и сохранение предыдущего Drive-pointer при ошибке копирования. Это проверки определений из основного notebook, не запуск всего Colab workflow.

`docs/colab_local_checks.json` и `docs/colab_data_info.json` — фактические локальные проверки/размеры. `scripts/pack_colab_data.py` — уже выполненная локальная упаковка существующих frozen caches, повторять не требуется. `scripts/evaluate_colab_review.py` + `src/sandbox.py` — только локальная Docker-оценка; notebook от них не зависит. `configs/large_a100.json` — копия встроенного config, эквивалентность проверяется; эффективные настройки сохраняются самим запуском.

**Не проверено без облака:** Run all на реальной чистой Colab A100/T4; текущие предустановленные Torch/CUDA и совместимость с pinned Transformers; BF16/SDPA throughput и оптимальный physical batch; доступные RAM/диск; реальная скорость и поведение Drive; большой full-state resume на GPU; качество 106M модели; полная генерация1919 на T4 и прохождение180s. Малый CPU export/reload не доказывает идентичность между GPU/версиями. Финальные generated512 сохраняются по бюджету, отсутствующие явно пропускаются evaluator. Официальный public pass@1 неизвестен.

Старые baseline/данные/эксперименты не менялись. Архив прежних исходников, configs, notebooks и отчётов: `archive/colab_migration_20261023/legacy_sources.zip`; прежние веса оставлены на исходных местах, без дублирования и поломки provenance. Старый `src/train.py` относится к прежним опытам, не является вторым training engine нового106M запуска. Нового `src/colab` нет. Новое обучение автоматически локально не запускается.
